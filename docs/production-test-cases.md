# 个人工作台生产版完整测试与发布基线

> 对齐：`architecture.md` @ 2026-08-03。  
> 规则：P0 任一失败禁止发布；安全、RLS、迁移、数据完整性用例无条件按 P0 执行。

## 1. 测试层级与环境

| 层级 | 工具 | 覆盖 |
|---|---|---|
| 单元 | Vitest | 解析、排序、标题、搜索高亮、URL、容量、日期、AI 合并 |
| 组件 | Testing Library | 表单、菜单、弹层、焦点、键盘、错误态 |
| 数据库 | Supabase local + SQL/pgTAP | 约束、事务、RLS、迁移、索引 |
| 接口 | Vitest/undici | Auth、DTO、错误码、幂等、超时、SSRF |
| E2E | Playwright | 桌面/手机核心链路、多标签、上传、拖拽 |
| 性能 | Lighthouse + k6 | Web Vitals、1000 项、并发、API P95 |
| 安全 | ZAP + 定向测试 | XSS、CSRF、SSRF、越权、上传、密钥泄露 |

测试数据不得使用生产数据。关键矩阵：Chromium/WebKit/Firefox；iPhone SE 320px、390px、iPad、1366px、1920px；100%/200% 缩放；鼠标、键盘、触控；中文输入法、英文、日韩文、Emoji、RTL。

## 2. 功能边界验收

| ID | 边界 | 通过标准 |
|---|---|---|
| B-01 | 单用户私有工作台 | 用户只能看见自己的数据，不存在共享入口 |
| B-02 | 心情未实现 | 桌面和手机导航均完全隐藏，不显示占位或“即将开放”，无可访问死入口 |
| B-03 | AI 仅整理单条记录 | 不读其他记录，不自动覆盖，不处理附件原文件 |
| B-04 | 非完整离线产品 | 断网有明确状态，不声称已云端保存 |
| B-05 | 资料编辑器范围 | 保持已确认交互，不扩展复杂 Office 功能 |
| B-06 | 删除规则 | 普通内容立即删除+5秒撤销；不可逆账号操作确认 |

## 3. P0 核心用例

### 3.1 账号与隔离

| ID | 场景 | 预期 |
|---|---|---|
| AUTH-01 | 邮箱登录、退出、刷新、会话过期 | 状态准确；受保护页跳登录；登录后回原页 |
| AUTH-02 | 错误/过期/重复使用链接 | 明确错误，不建立会话 |
| AUTH-03 | A/B 用户读取、修改、删除对方每张表记录 | 全部被 RLS 拒绝，响应不泄露记录存在性 |
| AUTH-04 | 伪造 `user_id`、JWT、Storage 路径 | 服务端忽略/拒绝，无越权 |
| AUTH-05 | 多设备同时登录、一个设备退出 | 会话按策略工作，不误删数据 |

### 3.2 【今日事】（安排域）

| ID | 场景 | 预期 |
|---|---|---|
| TASK-01 | 今日/后续新增、预计完成日期选填，空格、200字、同名 | 空格拒绝，边界正确，同名允许；未填日期不显示占位 |
| TASK-02 | 完成/恢复普通和 P0 事项 | 位置不变；P0 标签保留；图标按既定状态展示 |
| TASK-03 | 组内排序、跨区移动、空区落点、取消拖拽 | 顺序和区域准确，刷新/另一设备一致 |
| TASK-04 | 删除并在 4.9s 撤销、5.1s 后撤销 | 前者恢复原位，后者明确失效 |
| TASK-05 | 后续安排筛选：全部、本周、下周、本月 | 日期边界按用户时区计算；未填日期事项仅在全部中展示 |
| TASK-06 | 到期与超期迁移 | 仅未完成后续事项在到期日移入今日；错过打开时下次进入首页补做迁移并标记“已逾期 · M/D”；无预计完成日期的今日跨日未完成事项仅标记“已逾期”；已完成事项不移动 |
| TASK-07 | 完成记录与隐藏已完成 | 不显示“来自今日／来自后续”；有日期显示原计划日期；已完成事项完成当天可见、次日自动隐藏，且全局隐藏开关仍生效 |
| TASK-08 | 既有样式沿用 | 新增仍为现有置顶输入框；“已逾期”与原“昨日遗留”标签视觉一致，仅文案不同；后续安排背景色与原本周安排一致 |

## 6. 安全专项（全部 P0）

| ID | 场景 | 预期 |
|---|---|---|
| SEC-01 | 所有表/Storage 的横向越权 | RLS/Storage policy 全拒绝 |
| SEC-02 | 未登录直接调用所有写 API | 401；无数据变化 |
| SEC-03 | CSRF/跨源请求 | Cookie/SameSite/Origin 校验有效 |
| SEC-04 | SSRF：localhost、内网、IPv6、十进制IP、DNS rebinding、重定向内网 | 全部阻止并审计 |
| SEC-05 | XSS：正文、标题、文件名、URL、AI结果 | 无脚本执行，CSP 不报警或仅预期阻止 |
| SEC-06 | 上传伪造 MIME、双扩展、恶意 SVG/HTML、超大压缩文件 | 拒绝或强制下载，不内联执行 |
| SEC-07 | Git、浏览器包、source map、日志扫描密钥 | 无 service role/OpenRouter Key/Token |
| SEC-08 | 暴力登录、接口刷取、AI滥用 | 限流生效，正常用户有明确反馈 |
| SEC-09 | signed URL 过期、替换路径、猜测 UUID | 过期/越权均拒绝 |
| SEC-10 | 删除账号与数据导出 | 需重新认证；导出仅本人；清理完整可审计 |

## 10. 自动化映射

- 每条 P0 至少一个自动化测试；无法自动化的真实设备、读屏、拖拽手感列入人工验收并保留证据。
- 每个 bug 修复必须先增加失败用例，再修复，再跑相关模块和通用组件回归。
- Playwright 核心旅程：注册登录 → 四模块各新增一项 → 排序/移动 → 搜索 → 删除撤销 → 刷新 → 第二浏览器确认同步。
- CI 固定命令：`lint`、`typecheck`、`test:unit`、`test:integration`、`test:rls`、`test:e2e`、`build`。

## 11. 发布门槛与上线清单

### 阻断条件

- 任一 P0、RLS、安全、迁移或数据恢复用例失败。
- 数据丢失、误覆盖、跨用户泄露、死按钮、无法退出的弹层、阻塞性控制台错误。
- 生产密钥进入 Git/客户端包/日志。
- 数据库变更没有回滚方案或备份未验证。

### 上线步骤

1. 冻结需求和数据库迁移；生成测试报告。
2. Preview 环境跑全量自动化和桌面/手机人工验收。
3. 备份生产库；运行兼容性迁移；验证 RLS。
4. 部署 Vercel Production；执行 smoke tests。
5. 观察错误率、登录、保存、AI、元数据、上传指标至少30分钟。
6. 异常先回滚应用；数据库只执行已演练的回滚/前向修复。
7. 更新版本、commit、迁移号、测试证据和已知限制。

## 12. 给实现模型的执行规则

1. 不得跳过或改写 P0；不得用“构建成功”宣称可上线。
2. 开发前先把本文件 ID 映射到测试文件；每完成一个功能同步完成测试。
3. 不得把 service role/OpenRouter Key 暴露给客户端，不得关闭 RLS 解决权限问题。
4. 产品规则有歧义时停止该分支并记录，不得自行发明交互；可继续实现不受影响部分。
5. 所有数据库变更必须 migration 化；不得手改生产库。
6. 任何乐观更新失败必须回滚 UI 并提示；不得显示虚假“已保存”。
7. 发布报告必须分别列出：已实现、自动测试、人工验证、未完成、已知风险。
